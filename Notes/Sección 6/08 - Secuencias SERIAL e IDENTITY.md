# Secuencias, SERIAL e IDENTITY

Una secuencia genera números independientes que suelen utilizarse como valores predeterminados de una columna identificadora.

## Secuencia explícita

```sql
CREATE SEQUENCE IF NOT EXISTS language_code_seq;

CREATE TABLE language (
    code integer NOT NULL
        DEFAULT nextval('language_code_seq'::regclass),
    name text NOT NULL UNIQUE,
    CONSTRAINT language_pkey PRIMARY KEY (code)
);
```

La secuencia y la columna son objetos relacionados, pero creados explícitamente.

## SERIAL

```sql
CREATE TABLE departments_s6 (
    id serial PRIMARY KEY,
    name varchar(40) NOT NULL UNIQUE
);
```

`SERIAL` es una abreviatura histórica que crea una secuencia y configura `nextval(...)` como default. No es un tipo independiente real.

## IDENTITY

Para tablas nuevas suele preferirse la sintaxis estándar:

```sql
CREATE TABLE departments_s6 (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name varchar(40) NOT NULL UNIQUE
);
```

- `GENERATED ALWAYS`: normalmente PostgreSQL genera el valor.
- `GENERATED BY DEFAULT`: permite proporcionar uno manualmente con más facilidad.

## Lo que una secuencia no garantiza

- No genera números necesariamente consecutivos.
- Un rollback puede dejar huecos.
- El orden numérico no debe interpretarse automáticamente como orden de negocio.
- Generar un número no reemplaza la PK; la unicidad sigue siendo responsabilidad del constraint.

## Evitar colisiones tras cargas manuales

Si se insertan IDs explícitos en una tabla basada en secuencia, quizá sea necesario sincronizarla:

```sql
SELECT setval(
    pg_get_serial_sequence('language', 'code'),
    COALESCE((SELECT MAX(code) FROM language), 1),
    true
);
```

No hace falta ejecutar esto si todos los IDs se generaron normalmente.
